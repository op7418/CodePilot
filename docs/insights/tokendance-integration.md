# TokenDance：授权后仍是一条普通服务商连接

> 技术实现见 [docs/handover/tokendance-integration.md](../handover/tokendance-integration.md)。

用户希望在 CodePilot 中使用 TokenDance，并保留统一的授权、归因和恢复体验。TokenDance 授权实际创建 API Key，因此接入应落到原有服务商连接，避免凭空增加一种订阅身份或另一套聊天数据。重新授权只替换原连接的 Key，用户原来的模型配置和聊天继续保留。

同一 Key 可以调用多种协议，但模型可用协议并不相同。用户反馈说明：为 Claude Code 再添加一次连接会造成不必要的困惑。因此添加入口收敛为一条，同一连接按 Runtime 选择协议，并按模型实际声明筛选可用性。当前精选模型中，Kimi K3 只支持 Native/Codex，其余五款可在 Claude Code 使用。保留旧连接身份与聊天，避免把功能补齐变成用户的数据迁移。

全部展示会淹没常用选择。用户指定默认六款：GLM 5.3、Kimi K3、MiniMax 最新聊天型号 M3、DeepSeek V4 Flash/Pro、GLM 5.3 Flash。名单精确匹配实时目录，其他模型可在管理页启用；手动隐藏、启用和编辑优先于系统推荐。公开模型仍不等于账号已获得访问权限。

用户可选择手填 Key，或在 TokenDance 页面确认授权范围后回到客户端。浏览器无法回到本机时可以粘贴一次性授权码；这不是粘贴长期 Key。密钥只保存在既有服务端加密存储中。授权与手动保存互斥，减少“点了两次，创建两份连接”的意外。

余额不足、Key 失效和周期额度用尽是三种不同问题。根据官方恢复头明确引导，避免让余额不足的用户反复重新授权，也不擅自删除可能仍有效的 Key。充值由用户在 TokenDance 完成；本轮没有代用户付款或自动购买的功能。

公开目录与模拟上游验证不足以证明真实授权、模型 entitlement、计费和 Windows 打包路径可用。这些边界在交接中保留。模型的 Claude Code 兼容性目前采用有来源日期的协议快照，未知模型保守隐藏；后续若实现实时能力缓存，应明确失效与漂移行为。图像、语音、支付仍是独立产品范围，不能仅把更多 endpoint 加进现有 allowlist。


审查后的语义收尾：服务商整体支持多个 Runtime，不代表旗下每个模型都具有相同能力。Provider 标签应说明多协议，Models 筛选按每个模型判断；代理分类则说明该连接实际使用的协议。目录中的 Chat Completions 声明也不证明模型适合通用聊天，TTS 可能使用同一协议，因此文档只承诺协议筛选和六款默认精选。
